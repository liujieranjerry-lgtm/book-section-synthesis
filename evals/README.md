# 评测

这个目录用来验证 skill 的**行为**，不只是文件结构。`scripts/validate.py` 只能检查 frontmatter、命名和必需文件；它不能证明 skill 会正确拒答、正确划边界或正确区分原文与推断。

## 前向测试流程

1. 使用一个独立的 agent 或模型实例，不要在同一个对话里让它先读预期答案。
2. 给它 skill 目录和一个 fixture，例如：
   `Use the skill at /path/to/book-section-synthesis to complete this realistic request: ...`
3. 只提供完成任务所需的最小原始材料；不要提供预期输出、已知 bug 或修复建议。
4. 保存完整的用户—agent 交互和最终输出。
5. 按 [rubric.md](rubric.md) 逐项评分，并记录模型、版本、日期和 skill 版本。
6. 对失败项做最小修复；修复行为时同步增加或更新 fixture。

## 评分要求

- 不要用“措辞是否与参考一致”评分。评分看行为不变量：是否拒答无原文请求、是否划对边界、是否区分原文与推断、是否按文本类型组织、篇幅是否符合模式。
- 评分时同时看交互过程和最终输出。例如，缺少原文时，正确行为是在输出正文之前要求用户提供原文，而不是先写一段再补一句“请提供原文”。
- 至少使用一个与开发时不同的模型或不同的随机种子跑一遍，检查行为是否稳定。
- 负面用例（无原文、越界、注入、事实争议）优先跑。

## 结果的解读

- 总分不是唯一标准。`source gate`、`fidelity`、`boundary` 任一为 0，整体不通过。
- 通过阈值建议为 14/18，且 `source gate`、`fidelity`、`boundary` 均不低于 1。
- 若同一用例在不同模型上结果差异很大，说明该行为对模型版本敏感；在 README 的“已验证模型”一节记录，并考虑把关键规则写得更显式。
