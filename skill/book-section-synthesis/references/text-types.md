# 文本类型判定与骨架

这份参考解决一个具体问题：教材小节的写法不止一种。把定义型、分类型、过程型或机制型的小节硬写成“作者提出主张—反驳—结论”，会系统性扭曲原文。先判类型，再选骨架。

## 判定方法

按顺序问三个问题：

1. **这一节的主要动作是什么？** 是在证明一个主张、界定一个概念、把对象分类、描述一个过程、比较两个对象、解释一个机制，还是叙述一段历史？
2. **标题和段落的组织信号是什么？** 看小标题、连接词、反复出现的句式，而不是只看关键词。
3. **如果删掉“结论”或“反驳”，这一节还成立吗？** 如果照样成立，它很可能不是论证型，不要强行补出结论。

判定结果以“主导类型”为准。混合类型很常见，例如“先定义、再分类、最后用一个案例说明”，此时用定义型或分类型的骨架为主，把案例作为其中一个环节，而不是另起一套论证叙事。

## 论证型

**典型结构**：问题 → 主张 → 理由 → 反驳或限定 → 结论。

**识别信号**：出现“因此”“由此可见”“有人会反对”“这种说法的问题在于”“更准确地说”等推进词；段落之间有明显的支持或反驳关系。

**写法要点**：

- 先写清楚这一节要回答的问题，再写作者的主张。
- 每个理由都要说明它支持什么，不要只罗列理由。
- 反驳或限定要写清楚它针对的是哪一步推理。
- 如果作者没有给出结论，不要替作者补一个更强的结论。

**常见错误**：把“提出问题”直接写成“作者反对某观点”；把例子当成独立论点；为了结构完整而虚构“反对意见”。

## 定义型

**典型结构**：术语 → 界定 → 区分 → 例子 → 边界。

**识别信号**：出现“所谓……是指”“这里说的……不是……而是……”“区别于……”等句式；中心任务是让读者准确使用一个概念。

**写法要点**：

- 写清楚定义的对象和定义方式：属加种差、功能定义、操作定义、法律定义等。
- 写清楚它排除了什么，尤其是容易混淆的近义概念。
- 例子要说明它验证或澄清了定义的哪一部分。
- 边界条件、例外和争议要保留，不要为了简洁删掉。

**常见错误**：把定义型小节写成“作者主张某个定义”；用词典义替代作者在本文中的特定用法；忽略“不是……而是……”中真正被排除的对象。

## 分类型

**典型结构**：分类目的 → 分类标准 → 各类别 → 类别间比较。

**识别信号**：出现“可以分为”“第一类/第二类”“按……标准”“这三种类型”等；小节的核心是建立区分。

**写法要点**：

- 先写分类要解决的问题，再写分类标准。
- 每一类都要写清楚区分特征，而不是只列名称。
- 类别之间如果有重叠、层级关系或优先级，要明确说明。
- 如果作者给出了比较或评价，写清楚比较维度和结论。

**常见错误**：只复述类别清单；忽略分类标准；把并列类别误写成因果关系；把作者的类型学当成自然事实。

## 过程型

**典型结构**：目标 → 阶段 → 条件 → 结果。

**识别信号**：出现“首先/然后/接着”“第一步/第二步”“在……条件下”“最终形成”等；小节描述一个流程、机制发生过程或操作步骤。

**写法要点**：

- 先写过程的目标或起点，再写各阶段的输入、动作和输出。
- 写清楚阶段之间的条件或触发关系，不要只做步骤罗列。
- 如果某一步有失败条件、分支或回退，要保留。
- 结果要区分“过程结束时的状态”和“作者的评价”。

**常见错误**：把过程型写成论证型；把步骤顺序当成因果解释；漏掉条件分支。

## 比较型

**典型结构**：比较维度 → 对象 A 的特征 → 对象 B 的特征 → 异同 → 结论。

**识别信号**：出现“相比”“不同于”“相同之处在于”“一方面/另一方面”“两种路径”等；小节的主要动作是辨析异同。

**写法要点**：

- 先写比较的目的和维度；没有维度的比较会变成并列罗列。
- 每个维度下写清楚两个对象的差异，再写共同点。
- 如果作者有偏好或结论，明确写出来，并说明理由。
- 注意比较是否对称：作者是否只讲了 A 的优点和 B 的缺点。

**常见错误**：把比较型写成两个对象的独立介绍；忽略比较维度；把作者的偏好当成中立事实。

## 机制型

**典型结构**：现象 → 结构或要素 → 机制 → 证据 → 限制。

**识别信号**：出现“之所以……是因为”“其机制是”“通过……实现”“证据来自……”等；小节解释某现象如何产生或某系统如何运作。

**写法要点**：

- 先写要解释的现象或问题，再写机制涉及的要素。
- 机制要写成“要素 A 通过关系 R 导致结果 C”，而不是只写“存在某种关系”。
- 证据要说明它支持机制的哪一环。
- 限制、替代解释和未解决的问题要保留。

**常见错误**：把机制描述成过程步骤；把相关性写成因果；漏掉作者对机制适用范围的限定。

## 叙事型

**典型结构**：背景 → 转折 → 结果 → 意义。

**识别信号**：按时间推进，出现人物、事件、年代、阶段；小节通过历史或案例来建立观点。

**写法要点**：

- 先写叙事要说明的问题，再按关键转折组织，而不是按时间流水账。
- 事件之间的因果关系要写清楚：什么变化导致什么结果。
- 如果作者从叙事中提炼了意义或教训，单独写出来，不要与事件本身混在一起。
- 保留作者对史料的限定或争议。

**常见错误**：写成事件摘要；把叙事中的例子当成普遍规律；忽略作者的时间限定和地域限定。

## 描述/说明型

**典型结构**：对象 → 特征 → 关系 → 例证。

**识别信号**：介绍一个对象、系统、制度、文本或现象；没有明显的主张—反驳结构。

**写法要点**：

- 先写说明对象和说明目的。
- 特征要按功能或重要性组织，不要按出现顺序罗列。
- 对象与其他概念的关系要写清楚。
- 例证要说明它展示了哪一个特征。

**常见错误**：把说明型强行写成论证型；把描述性表述改写成规范性主张；忽略作者使用的分类框架。

## 混合类型的处理

1. 找出主导动作：这一节最花篇幅在做什么？
2. 用主导类型的骨架组织全文。
3. 把次要类型作为某个环节嵌入，例如“定义型主导，结尾用案例说明边界”。
4. 如果两种类型势均力敌，按原文的小标题顺序组织，并在每个小标题内部使用对应骨架。
5. 不要为了套骨架而删除原文中的重要限定或例外。

## 特殊文本

### 以图表、公式或表格为主的小节

先判断这些元素承担什么功能：是提供证据、定义变量、展示分类，还是仅作示意？承担论证功能的，要在对应环节写出它的作用和结论；纯装饰性的可以略过。无法读取的图表或公式标记 `[无法辨认]`，不要根据上下文猜内容。

### 脚注和尾注

脚注可能包含定义、限定、反驳或来源信息。快速判断：如果删掉这条注释，正文的主张是否会被误解？会，就把它写进对应环节；不会，就不必强行纳入。引用注释时说明它来自注释。

### 定理—证明型

按“定理陈述 → 证明策略 → 关键步骤 → 结论”组织。不要用“作者主张”这种论证文语言；数学证明的“因此”是推导，不是修辞。

### 案例型

按“案例背景 → 关键冲突或变量 → 处理方式 → 结果 → 作者用它说明什么”组织。案例本身不等于普遍结论；作者是否做了推广，要单独说明。

### 对话或访谈型

按“参与者的立场 → 分歧点 → 论证或回应 → 是否达成结论”组织。不要把提问者的引导性表述写成被访者的主张。

## 判定失败时

如果读完仍然无法判断类型：

- 按原文的小标题和段落功能组织；
- 先写“这一节处理的问题或对象”，再逐段说明它在做什么；
- 不要强行补“反对意见”“结论”或“作者立场”；
- 在输出开头说明你采用了哪种组织方式。
